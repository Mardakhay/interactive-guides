Section 01

Why Do We Need an API Layer?

Before we write a single line of the solution, let's understand what problem we're solving.

❌ The Problem — Code Without API Layer

Imagine you have 5 components that all fetch users. You'd write the same fetch() call 5 times. Then your API URL changes — now you edit 5 files. One catch is slightly different — now you have 5 bugs.

⚠️

DRY Principle Violation

"Don't Repeat Yourself" — every piece of knowledge should have a single, authoritative representation in your codebase.

✅ The Solution — Centralized API Layer

♻️

🔧
Easy to change

🧪

Section 03

Axios Client Setup

Axios is a library that makes HTTP requests easier than the built-in fetch(). Let's see why, then configure it properly.

fetch() vs Axios — Side by Side

With fetch() — verbose
const res = await fetch('/users');

// Must manually check status!
if (!res.ok) {
  throw new Error('Failed');
}

// Must manually parse JSON
const data = await res.json();

// No timeout support built-in
// No request/response interceptors
// Must set headers manually every time
With Axios — clean
// Axios auto-throws on 4xx/5xx
const { data } = await
  apiClient.get('/users');

// ✅ Auto JSON parsing
// ✅ Auto error on bad status
// ✅ baseURL — no repeating
// ✅ Interceptors (add token, etc.)
// ✅ Timeout support
// ✅ Request cancellation

Creating the Axios Instance

api/client.ts
import axios from 'axios';

// 1. Create your custom Axios instance
const apiClient = axios.create({
  baseURL: 'https://jsonplaceholder.typicode.com',  // 👈 all URLs are relative to this
  timeout: 10000,          // 👈 fail if no response in 10 seconds
  headers: {
    'Content-Type': 'application/json',
  },
});

// 2. Request Interceptor — runs BEFORE every request is sent
apiClient.interceptors.request.use(
  (config) => {
    // Automatically attach auth token if it exists
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;  // must return config!
  }
);

// 3. Response Interceptor — runs AFTER every response arrives
apiClient.interceptors.response.use(
  (response) => response,  // ✅ success — pass through unchanged
  (error) => {
    if (error.response) {
      // Server responded with an error status (4xx, 5xx)
      switch (error.response.status) {
        case 401:  // Unauthorized — not logged in
          localStorage.removeItem('token');
          window.location.href = '/login';
          break;
        case 403:  // Forbidden — logged in but no permission
          console.error('Access denied!');
          break;
        case 404:  // Not found
          console.error('Resource not found');
          break;
        case 500:  // Server crashed
          console.error('Server error — try again later');
          break;
      }
    } else if (error.request) {
      // Request made but no response — network issue
      console.error('Network error — are you offline?');
    }
    return Promise.reject(error);  // always re-throw!
  }
);

export default apiClient;

Section 04

Service Files

Service files contain all the actual API calls. They are plain async functions grouped by resource. No React, no state — just pure data fetching logic.

CRUD Operations — The Full Pattern

CRUD stands for Create, Read, Update, Delete — the four fundamental operations for any data resource.

GET Read

Fetch data from the server. Doesn't change anything.

POST Create

Send new data to create a resource on the server.

PUT/PATCH Update

Modify existing data. PUT = full replace, PATCH = partial.

DELETE Delete

Remove a resource from the server permanently.

api/userService.ts
import apiClient from './client';
import { User } from './types';

const userService = {
  // READ — get all users
  getAll: async (): Promise<User[]> => {
    const { data } = await apiClient.get<User[]>('/users');
    return data;
  },

  // READ — get one user by ID
  getById: async (id: number): Promise<User> => {
    const { data } = await apiClient.get<User>(`/users/${id}`);
    return data;
  },

  // CREATE — send a new user
  // Omit<User, 'id'> means: User without the 'id' field
  // (server assigns the ID)
  create: async (user: Omit<User, 'id'>): Promise<User> => {
    const { data } = await apiClient.post<User>('/users', user);
    return data;
  },

  // UPDATE — replace user data (full update)
  // Partial<User> means: any subset of User fields is OK
  update: async (id: number, user: Partial<User>): Promise<User> => {
    const { data } = await apiClient.put<User>(`/users/${id}`, user);
    return data;
  },

  // DELETE — remove a user
  delete: async (id: number): Promise<void> => {
    await apiClient.delete(`/users/${id}`);
  },

  // SEARCH — filter by query string
  search: async (query: string): Promise<User[]> => {
    const { data } = await apiClient.get<User[]>('/users', {
      params: { q: query }   // → GET /users?q=john
    });
    return data;
  },
};

export default userService;
api/postService.ts
import apiClient from './client';
import { Post, Comment } from './types';

const postService = {
  getAll: async (): Promise<Post[]> => {
    const { data } = await apiClient.get<Post[]>('/posts');
    return data;
  },

  getById: async (id: number): Promise<Post> => {
    const { data } = await apiClient.get<Post>(`/posts/${id}`);
    return data;
  },

  // Get ALL posts by a specific user — nested route!
  getByUserId: async (userId: number): Promise<Post[]> => {
    const { data } = await apiClient.get<Post[]>(`/users/${userId}/posts`);

  getComments: async (postId: number): Promise<Comment[]> => {
    const { data } = await apiClient.get<Comment[]>(`/posts/${postId}/comments`);

  },

  create: async (post: Omit<Post, 'id'>): Promise<Post> => {
    const { data } = await apiClient.post<Post>('/posts', post);
    return data;
  },
};

Section 05

Custom Hooks

Custom hooks let you extract stateful logic out of components. A custom hook is just a function starting with use that can call other hooks.

🪝

Why Custom Hooks?

Without custom hooks, you'd have useState, useEffect, try/catch, and loading logic duplicated in every component that fetches data. Custom hooks extract this into one reusable place.

useUsers — Full Breakdown

hooks/useUsers.ts
import { useState, useEffect } from 'react';
import userService from '../api/userService';
import { User } from '../api/types';

function useUsers() {
  // Three pieces of state for any data fetch:
  const [users, setUsers] = useState<User[]>([]);          // the data
  const [loading, setLoading] = useState<boolean>(true);    // is it loading?
  const [error, setError] = useState<string | null>(null);  // error message

  const fetchUsers = async () => {
    try {
      setLoading(true);
      setError(null);                      // clear previous errors
      
      const data = await userService.getAll();
      setUsers(data);
      
    } catch (err) {
      // Safe error message extraction
      setError(err instanceof Error ? err.message : 'An error occurred');
    } finally {
      setLoading(false);  // ALWAYS stop loading — success OR failure
    }
  };

  // Run on mount (empty array = run once when component mounts)
  useEffect(() => {
    fetchUsers();
  }, []);

  // Return what components need — data + state + refetch
  return { users, loading, error, refetch: fetchUsers };
}

export default useUsers;

How the Component Uses It

components/UserList.tsx
import useUsers from '../hooks/useUsers';

function UserList() {

  const { users, loading, error, refetch } = useUsers();

    <div>

    </div>

    <ul>
      {users.map(user => (
        <li key={user.id}>
          <strong>{user.name}</strong> — {user.email}
        </li>
      ))}
    </ul>
  );
}

usePosts — With Optional Filter

hooks/usePosts.ts
import { useState, useEffect } from 'react';
import postService from '../api/postService';
import { Post } from '../api/types';

// userId is OPTIONAL — can show all posts or filtered by user
function usePosts(userId?: number) {
  const [posts, setPosts] = useState<Post[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const fetchPosts = async () => {
    try {
      setLoading(true);
      setError(null);
      
      // Conditional fetch based on whether userId was passed
      const data = userId
        ? await postService.getByUserId(userId)  // → /users/5/posts
        : await postService.getAll();              // → /posts
      
      setPosts(data);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Error');
    } finally {
      setLoading(false);
    }
  };

  // Re-fetch whenever userId changes!
  useEffect(() => { fetchPosts(); }, [userId]);

  return { posts, loading, error, refetch: fetchPosts };
}

export default usePosts;

// Usage examples:
// usePosts()      → all posts
// usePosts(5)     → only user 5's posts
// usePosts(userId) → reactive: refetches when userId changes

useFetch — The Universal Generic Hook

Why write the same loading/error/data pattern 10 times? useFetch is a reusable hook that works with any async function.

hooks/useFetch.ts
import { useState, useEffect, useCallback } from 'react';

// Generic interface — T can be any type (User, Post[], Comment, etc.)
interface UseFetchResult<T> {
  data: T | null;
  loading: boolean;
  error: string | null;
  refetch: () => void;
}

function useFetch<T>(
  fetchFn: () => Promise<T>,   // 👈 accepts ANY async function
  deps: any[] = []               // 👈 re-run when these change
): UseFetchResult<T> {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const execute = useCallback(async () => {
    try {
      setLoading(true);
      setError(null);
      const result = await fetchFn();
      setData(result);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Error');
    } finally {
      setLoading(false);
    }
  }, deps);

  useEffect(() => { execute(); }, [execute]);

  return { data, loading, error, refetch: execute };
}

export default useFetch;

// ============ USAGE — So clean! ============

// All users
const { data: users, loading } = useFetch(() => userService.getAll());

// One user (re-fetches when userId changes)
const { data: user } = useFetch(() => userService.getById(userId), [userId]);

// User's posts (nested resource)
const { data: posts } = useFetch(() => postService.getByUserId(userId), [userId]);

// Comments for a post
const { data: comments } = useFetch(() => postService.getComments(postId), [postId]);

useSearch — Debounced Search

Debouncing means: wait until the user stops typing before triggering the search. Without it, you fire an API call on every single keystroke.

⚡

Why Debounce Matters

If you type "john" (4 letters) in a search box, without debounce you make 4 API calls: "j", "jo", "joh", "john". With a 300ms debounce, you make just 1 — only when you pause typing.

hooks/useSearch.ts
import { useState, useEffect, useMemo } from 'react';

function useSearch<T>(
  items: T[],                      // The full list to search through
  searchFields: (keyof T)[],       // Which fields to search on
  delay: number = 300             // Debounce delay in ms
) {
  const [query, setQuery] = useState('');               // live input value
  const [debouncedQuery, setDebouncedQuery] = useState(''); // delayed value

  // DEBOUNCE: Only update debouncedQuery after 300ms of no typing
  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedQuery(query);
    }, delay);
    
    // Cleanup: cancel previous timer if user types again
    return () => clearTimeout(timer);
  }, [query, delay]);

  // FILTER: Only recalculate when debouncedQuery or items change
  const filtered = useMemo(() => {
    if (!debouncedQuery.trim()) return items; // empty query → all items
    
    const lower = debouncedQuery.toLowerCase();
    
    return items.filter(item =>
      searchFields.some(field => {
        const value = String(item[field]);
        return value.toLowerCase().includes(lower);
      })
    );
  }, [items, debouncedQuery, searchFields]);

  return { query, setQuery, filtered, debouncedQuery };
}

export default useSearch;

// ========= Usage in component: =========
function UserList() {
  const { users } = useUsers();
  const { query, setQuery, filtered } = useSearch(
    users,
    ['name', 'email', 'username']  // search these 3 fields
  );
  
  return (
    <div>
      <input
        value={query}
        onChange={e => setQuery(e.target.value)}
        placeholder="Search users..."
      />
      <ul>
        {filtered.map(user => <li key={user.id}>{user.name}</li>)}
      </ul>
    </div>
  );
}

Section 06

Error Handling & Retry

Good apps don't just crash — they tell users what went wrong and give them a way to recover.

Types of API Errors

Error Type When It Happens error.response error.request Action
Network Error No internet, server down undefined exists Show "Check connection"
401 Unauthorized Token expired / not logged in exists — Redirect to login
403 Forbidden Logged in but no permission exists — Show "Access denied"
404 Not Found Resource doesn't exist exists — Show "Not found"
500 Server Error Server crash / bug exists — Show "Try again later" + retry

Centralized Error Handler

api/errorHandler.ts
import { AxiosError } from 'axios';

interface ApiError {
  message: string;
  status?: number;
  isRetryable: boolean;  // should we show a retry button?
}

export function handleApiError(error: unknown): ApiError {
  if (error instanceof AxiosError) {
    const status = error.response?.status;
    
    // Network error — no response received
    if (!error.response) {
      return {
        message: 'Network error — check your connection',
        isRetryable: true,  // network might come back!
      };
    }

    if (status === 401) {
      return { message: 'Please log in again', status, isRetryable: false };
    }

    if (status === 403) {
      return { message: 'Access denied', status, isRetryable: false };
    }

    if (status === 404) {
      return { message: 'Resource not found', status, isRetryable: false };
    }

    // 500+ — server errors are retryable
    if (status && status >= 500) {
      return { message: 'Server error — try again later', status, isRetryable: true };
    }
  }

  // Unknown error
  return { message: 'An unexpected error occurred', isRetryable: false };
}

Retry with Exponential Backoff

📈

What is Exponential Backoff?

Instead of retrying immediately (which could overwhelm a struggling server), you wait longer between each attempt: 1s → 2s → 4s → 8s. This gives the server time to recover.

utils/retry.ts
async function withRetry<T>(
  fn: () => Promise<T>,
  maxRetries: number = 3,
  delay: number = 1000
): Promise<T> {
  let lastError: Error;

  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn();                        // ✅ success → return immediately
    } catch (error) {
      lastError = error as Error;
      console.log(`Attempt ${i + 1}/${maxRetries} failed`);

      if (i < maxRetries - 1) {
        // Exponential backoff: 1000ms → 2000ms → 4000ms
        const waitTime = delay * Math.pow(2, i);
        console.log(`Waiting ${waitTime}ms before retry...`);
        await new Promise(r => setTimeout(r, waitTime));
      }
    }
  }

  throw lastError!;  // all retries exhausted
}

// Usage in a service:
const getAll = async (): Promise<User[]> => {
  return withRetry(
    () => apiClient.get<User[]>('/users').then(r => r.data),
    3,    // max 3 attempts
    1000  // start with 1s delay
  );
};

API Integration & Custom Hooks Quiz

Question 1 / 8

1. What is the main problem that an API layer solves?

✅ The API layer centralizes all API calls in one place, following the DRY (Don't Repeat Yourself) principle. Without it, you'd write the same fetch() boilerplate in every component that needs data.

2. Which layer is responsible for managing loading, error, and data state?

✅ Custom Hooks manage state (useState), side effects (useEffect), and bridge between services and components. Services are pure async functions with no React state.

3. What does finally do in a try/catch/finally block in a custom hook?

✅ finally runs regardless of success or failure. This guarantees setLoading(false) is always called — if you forget it, the spinner would spin forever after an error.

4. What is the purpose of a Request Interceptor in Axios?

✅ Request interceptors run before each request is sent. A common use case is attaching the user's auth token from localStorage to every request's Authorization header — automatically.

5. What does Omit<User, 'id'> mean in TypeScript?

✅ Omit<User, 'id'> is a TypeScript utility type that produces a new type identical to User but without the id field. When creating a new user, you don't send an ID — the server generates it.

6. Why do we need debouncing in a search hook?

✅ Without debouncing, typing "john" makes 4 requests: "j", "jo", "joh", "john". With a 300ms debounce, you only make 1 request when the user stops typing. This is much more efficient.

7. What does isRetryable: true in an error handler indicate?

✅ isRetryable tells the UI whether to show a "Try Again" button. Network errors and 500 errors might be temporary. But 404 (resource not found) or 403 (forbidden) won't change by retrying.

8. In usePosts(userId?: number), what does the ? after userId mean?

✅ The ? makes the parameter optional in TypeScript. usePosts() fetches all posts, while usePosts(5) fetches only posts by user #5. The hook handles both cases with a conditional fetch.
