📦 Section 1

JavaScript Objects

Objects are the fundamental building block of JavaScript. Nearly everything in JS is an object or behaves like one. Let's build a complete mental model.

📦
What is an Object?

An object is a collection of key-value pairs — like a container holding named data. Think of it as a filing cabinet: each drawer has a label (key) and contains something inside (value).

🔗
By Reference

Objects are stored by reference, not by value. Assigning an object to a variable doesn't copy it — both variables point to the same object in memory.

⚡
Mutable

Objects are mutable — you can add, change, or delete properties even after creation. Only Object.freeze() makes an object immutable.

Dot vs. Bracket Notation

Both access properties, but they have different use cases. Dot notation is clean and readable; bracket notation is powerful for dynamic keys.

javascript
const user = { name: "Bob", "user-id": 42 };

// Dot notation — clean, preferred
user.name;                 // "Bob"

// Bracket notation — for dynamic keys or special chars
user["user-id"];           // 42  (hyphen = must use brackets)

const key = "name";
user[key];                 // "Bob"  (dynamic key lookup!)

// GOTCHA: dot notation doesn't work for...
user.user-id;             // ❌ SyntaxError
user.0;                   // ❌ SyntaxError
🧒 Explain Like I'm 5
🧒 ELI5: Imagine your backpack has pockets. You can reach in and say "give me my snack" (dot notation). OR you can write "snack" on a sticky note and give it to a robot who reaches in for you (bracket notation). Both get you the snack — but the robot version works even if you don't know the pocket name until later!

Passing by Reference

💡
Key concept: Primitives (strings, numbers) are copied when assigned. Objects are referenced — multiple variables can point to the same object. Mutating through one variable affects all references.
javascript
const a = { x: 1 };
const b = a;             // b points to SAME object

b.x = 99;
console.log(a.x);        // 99 — a was mutated too!

// To truly copy: use spread or Object.assign
const copy = { ...a };    // shallow copy
copy.x = 0;
console.log(a.x);        // 99 — original unchanged

Object Built-in Methods

javascript
const obj = { a: 1, b: 2, c: 3 };

Object.keys(obj);          // ["a", "b", "c"]
Object.values(obj);        // [1, 2, 3]
Object.entries(obj);       // [["a",1], ["b",2], ["c",3]]

// Merge objects
const merged = Object.assign({}, obj, { d: 4 });
// Or with spread:
const merged2 = { ...obj, d: 4 };

// Freeze (immutable)
const frozen = Object.freeze({ x: 1 });
frozen.x = 99;           // silently fails (or throws in strict mode)
console.log(frozen.x);   // still 1

🔗 Section 2

Prototypes & The Chain

This is where JavaScript gets powerful — and where most developers are missing crucial knowledge. Understanding prototypes is the key to truly understanding JS.

⚠️
Why this matters: Classes, extends, instanceof, and new are all built on prototypes. Once you understand the chain, everything else clicks into place.

What is [[Prototype]]?

Every object in JavaScript has a hidden internal slot called [[Prototype]] (written in double brackets to indicate it's internal). This slot is either null or points to another object — its prototype. When you access a property, JS checks the object first, then walks up this chain.

[[Prototype]]

The actual internal reference. You can't access it directly (it's an internal slot). Object.getPrototypeOf(obj) is the proper API to read it.

__proto__

The legacy getter/setter that exposes [[Prototype]]. Works, but deprecated. Use Object.getPrototypeOf instead. Still useful for understanding.

.prototype

Only on functions. When you call a function with new, the new object's [[Prototype]] is set to Function.prototype. Not the same as [[Prototype]]!

🧒 Explain Like I'm 5
🧒 ELI5: Imagine you need scissors. You look in your own room — no scissors. You go ask your parent — they don't have any. You go ask your grandparent — they have scissors! That's the prototype chain: if you don't have something, JS asks your "parent" object. And their "parent". Until it either finds it or runs out of ancestors (reaches null).

Object.create() — Manual Prototype Setting

Object.create(proto) creates a new object whose [[Prototype]] is set to proto. This is the most explicit way to set up prototype inheritance.

javascript
const animal = {
  breathe() {
    return `${this.name} inhales oxygen`;
  }
};

// Create dog with animal as its [[Prototype]]
const dog = Object.create(animal);
dog.name = "Rex";

dog.breathe();  // "Rex inhales oxygen"
// 'breathe' is NOT on dog — found on animal via [[Prototype]]

Object.getPrototypeOf(dog) === animal;  // true
dog.hasOwnProperty("breathe");           // false — inherited!
dog.hasOwnProperty("name");              // true — own property

Constructor Functions

Before ES6 classes, constructor functions were the way to create multiple objects of the same "type." They're still fundamental — classes are just syntactic sugar over them.

javascript
// Constructor function (capitalized by convention)
function Dog(name, breed) {
  // 'this' = the new object being created
  this.name = name;
  this.breed = breed;
}

// Methods on prototype = SHARED across all instances (memory efficient!)
Dog.prototype.bark = function() {
  return `${this.name} says: Woof!`;
};

const rex = new Dog("Rex", "Labrador");
const luna = new Dog("Luna", "Husky");

rex.bark();   // "Rex says: Woof!"
luna.bark();  // "Luna says: Woof!"

// Both share the SAME bark function — not duplicated!
rex.bark === luna.bark;  // true ✓ (memory efficient)
rex instanceof Dog;      // true

What new Actually Does

⚙️
The 4 steps of new: When you write new Dog("Rex"), JavaScript executes 4 hidden steps behind the scenes. Understanding these steps is the key to understanding ALL of JavaScript's object system.
javascript — What new does internally
// When you write: const rex = new Dog("Rex", "Labrador")
// JavaScript secretly does THIS:

function simulateNew(Constructor, ...args) {
  // Step 1: Create a new empty object
  const obj = {};

  // Step 2: Set its [[Prototype]] to Constructor.prototype
  Object.setPrototypeOf(obj, Constructor.prototype);

  // Step 3: Call the constructor with 'this' = new object
  const result = Constructor.apply(obj, args);

  // Step 4: Return obj (unless constructor returns its own object)
  return (typeof result === "object" && result !== null)
    ? result : obj;
}

// This is equivalent to: new Dog("Rex", "Labrador")
const rex = simulateNew(Dog, "Rex", "Labrador");
🧠 Why put methods on prototype? Memory optimization explained ▾

When you create 1000 Dog instances, you want bark() to exist only once in memory — not 1000 copies:

javascript
// ❌ BAD: bark() defined inside constructor
function Dog(name) {
  this.name = name;
  this.bark = function() { return "Woof!"; };
  // 1000 dogs = 1000 bark() function copies in memory 🔥
}

// ✅ GOOD: bark() on prototype
Dog.prototype.bark = function() { return "Woof!"; };
// 1000 dogs = 1 bark() function, shared via chain ✓
javascript — instanceof under the hood
// instanceof checks: is Constructor.prototype in obj's chain?
rex instanceof Dog;     // Is Dog.prototype in rex's [[Prototype]] chain? YES
rex instanceof Object;  // Is Object.prototype in rex's chain? YES (it's at the end)

// Manual equivalent:
Dog.prototype.isPrototypeOf(rex);  // true

ES6 Classes

Classes are syntactic sugar — elegant, readable syntax that compiles down to the exact same prototype-based patterns you just learned. Let's go deep.

🍬
Syntactic sugar explained: "Syntactic sugar" means nicer-looking syntax that does the same thing underneath. ES6 classes don't add new capabilities — they just make prototype-based code cleaner and more readable.

Classes vs. Constructor Functions — Side by Side

Constructor Function (ES5)
prototype-based
function Animal(name, sound) {
  this.name = name;
  this.sound = sound;
}

Animal.prototype.speak
  = function() {
  return `${this.name}: ${this.sound}`;
};

Animal.count = 0; // "static"

const cat =
  new Animal("Whiskers","meow");
Class Syntax (ES6+)
class syntax
class Animal {
  static count = 0;

  constructor(name, sound) {
    this.name = name;
    this.sound = sound;
  }

  speak() {
    return `${this.name}: ${this.sound}`;
  }
}

const cat =
  new Animal("Whiskers","meow");
✅
Both produce identical results. typeof Animal is still "function". The class body methods still go on Animal.prototype. Classes are just cleaner syntax.

extends & super — Inheritance

extends sets up the prototype chain automatically. super() calls the parent's constructor — and you must call it before using this in a subclass.

javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a sound.`;
  }
  toString() {
    return `[Animal: ${this.name}]`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);    // MUST call super first — initializes 'this'
    this.breed = breed;
  }

  speak() {                     // Overrides Animal.speak
    return `${this.name} barks!`;
  }

  describe() {
    return `${super.speak()} And barks.`;  // super.method() = parent's version
  }
}

const rex = new Dog("Rex", "Labrador");
rex.speak();      // "Rex barks!" (overridden)
rex.describe();   // "Rex makes a sound. And barks."
rex instanceof Dog;     // true
rex instanceof Animal;  // true (chain goes up!)
🔬 Under the Hood: What extends actually sets up ▾

class Dog extends Animal does TWO things with prototype chains:

prototype relationships
// 1. Instance chain — for method lookup on instances:
// rex.__proto__ === Dog.prototype
// Dog.prototype.__proto__ === Animal.prototype
// Animal.prototype.__proto__ === Object.prototype
// Object.prototype.__proto__ === null

// 2. Constructor chain — for static method inheritance:
// Dog.__proto__ === Animal  (so static methods are inherited too!)
// Animal.__proto__ === Function.prototype

// Verify it yourself:
Object.getPrototypeOf(Dog.prototype) === Animal.prototype; // true
Object.getPrototypeOf(Dog) === Animal;                  // true

This means rex can access methods from Dog.prototype AND Animal.prototype via the chain — that's inheritance!

Static Methods & Private Fields

javascript
class BankAccount {
  // Private field (truly private — not accessible outside)
  #balance = 0;
  #owner;

  // Static — belongs to class, not instances
  static interestRate = 0.03;
  static #totalAccounts = 0;

  constructor(owner, initialDeposit) {
    this.#owner = owner;
    this.#balance = initialDeposit;
    BankAccount.#totalAccounts++;
  }

  deposit(amount) {
    if (amount <= 0) throw new Error("Amount must be positive");
    this.#balance += amount;
    return this;  // method chaining!
  }

  // Getter — access like a property
  get balance() { return this.#balance; }

  // Static method — called on the class
  static getCount() {
    return BankAccount.#totalAccounts;
  }
}

const acc = new BankAccount("Alice", 1000);
acc.deposit(500).deposit(200);   // chaining!
acc.balance;                      // 1700
acc.#balance;                     // ❌ SyntaxError — truly private!
BankAccount.getCount();          // 1
BankAccount.interestRate;        // 0.03
