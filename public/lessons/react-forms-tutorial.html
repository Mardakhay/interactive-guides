01 — Introduction

Why Are Forms Important?

Forms are the primary way your application receives data from users. Almost every real-world web app relies on forms — from logging in, to searching, to buying products online. If you want to build anything useful, you need to understand forms.

Think about how often you fill out forms every day: logging into Gmail, searching on Google, paying on Amazon. All of that is powered by form inputs. In React, we have powerful tools to make this experience smooth and reliable.

Real-World Form Use Cases

🔐 Login / Register
🔍 Search & Filters
👤 Profile editing
💳 Payment & address forms
💬 Feedback & comments

What we'll cover

By the end of this course, you'll understand how to build forms in React using two different approaches (controlled and uncontrolled), validate user input, and use the industry-standard React Hook Form library.

💡
Beginner tip: Don't worry if this feels like a lot. Forms in React follow a consistent pattern — once you understand the logic behind controlled components, everything else clicks into place.
02 — Overview

Two Approaches to Forms

In React, there are two main ways to work with form inputs. Understanding the difference between them is the foundation of everything else in this course.

✅ Controlled — Recommended

React state manages the form data. Every keystroke updates state, and the input always shows what's in state. React is in full control.


useState onChange value prop

⚡ Uncontrolled — Less Common

The browser's DOM manages the form data. You only read the value when you need it (e.g., on submit). React steps back and lets the DOM do its thing.


useRef defaultValue ref.current.value
Real-world analogy

Controlled = You're steering the wheel. You know exactly where the car is at all times. Every turn is deliberate, and you have full control. If anything goes wrong, you immediately notice.

Uncontrolled = Autopilot. You set the destination and let the car drive. You only check in when you need to — like when you arrive. It's hands-off but you lose moment-to-moment awareness.

For most real-world forms, you want to be in control.

03 — Deep Dive

Controlled Components

A controlled component is a form input whose value is always synchronized with React state. React becomes the "single source of truth" — meaning the input on screen always exactly matches what's stored in state.

How It Works

User typeskeystroke event
→
onChange firesevent handler
→
setState calledupdates state
→
Re-renderinput shows new value

The four key rules of controlled components:

1️⃣
Input value is stored with useState

You create a state variable to hold the input's current value.

2️⃣
Every change is caught with onChange

The onChange event fires on every keystroke, calling your handler function.

3️⃣
The value prop is bound to state

The input element receives its value from state via the value prop. This "locks" the input to React's control.

4️⃣
React becomes the Single Source of Truth

The value in the input and the value in state are always identical — perfectly in sync.

ℹ️
Single Source of Truth means there's only ONE place where the data lives — React state. This makes your data predictable and easy to debug.

Basic Example — Single Input

ControlledInput.jsx
function ControlledInput() {
  // Step 1: Create state to hold the input's value
  const [name, setName] = useState('');

  return (
    <div>
      <input
        type="text"
        value={name}          // Step 3: Bind value to state
        onChange={(e) => setName(e.target.value)}  // Step 2: Update state on change
        placeholder="Enter your name"
      />
      <p>Hello, {name}!</p>   // State is always in sync
    </div>
  );
}
🔍
Try this mentally: When you type "A", onChange fires with e.target.value = "A". That calls setName("A"), which updates state, which causes React to re-render, which sets the input's value to "A". It all happens in milliseconds!

Multi-Field Form with a Single State Object

For forms with multiple fields (like a signup form), you don't want to create a separate useState for every single field. Instead, use one state object with all the fields:

SignupForm.jsx
function SignupForm() {
  // One state object for all fields
  const [formData, setFormData] = useState({
    name: '',
    email: '',
    password: ''
  });

  // One generic handler for ALL fields
  const handleChange = (e) => {
    const { name, value } = e.target;  // Destructure name and value
    // Spread the existing state, then override the changed field
    setFormData(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();  // Prevent page reload!
    console.log(formData);  // All field values are here
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="name"     value={formData.name}     onChange={handleChange} />
      <input name="email"    value={formData.email}    onChange={handleChange} />
      <input name="password" value={formData.password} onChange={handleChange} />
      <button type="submit">Sign Up</button>
    </form>
  );
}
🔑
The trick: The name attribute on each input matches the key in the state object. The [name]: value syntax (computed property name) dynamically updates whichever field changed. One handler covers all fields!
04 — Alternative Approach

Uncontrolled Components

In an uncontrolled component, the browser's DOM itself stores the input value — not React state. You use a ref (reference) to reach into the DOM and read the value whenever you need it, typically on form submission.

How It Works

What changes?

✔ No value prop on the input
✔ Use defaultValue instead of value
✔ No onChange needed
✔ Read value via ref.current.value

What's different internally?

React doesn't "know" what the user is typing. The input lives in the DOM, outside React's awareness. No re-renders happen on each keystroke.

Example

UncontrolledInput.jsx
function UncontrolledInput() {
  // useRef creates a reference to a DOM element
  const nameRef = useRef(null);

  const handleSubmit = (e) => {
    e.preventDefault();
    // Only read the value when we need it (on submit)
    const value = nameRef.current.value;
    console.log('Name:', value);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        ref={nameRef}              // Connect ref to this input
        defaultValue="John"       // Initial value (not controlled)
        type="text"
      />
      <button type="submit">Submit</button>
    </form>
  );
}
⚠️
Limitations of uncontrolled components:
  • Real-time validation (showing errors as you type) becomes very difficult
  • Not recommended for forms with many fields
  • Harder to programmatically reset or pre-fill values
📌
When to use uncontrolled: File upload inputs (where you can't control the value anyway), or extremely simple single-field forms where performance is the only concern.
05 — Side by Side

Controlled vs Uncontrolled

Feature ✅ Controlled ⚡ Uncontrolled
Data stored in React state (useState) The DOM itself
How to read value State variable (name) ref.current.value
Re-renders on typing Yes, every keystroke No re-renders
Real-time validation Easy ✔ Difficult ✗
Performance Can slow with many inputs Faster
Best used for Most real-world forms File uploads, simple one-off inputs
Integration with libraries Excellent Limited
The Golden Rule

Default to Controlled components. Unless you have a specific performance bottleneck you've measured, or you're dealing with file inputs, controlled components are the right choice. They're more predictable, debuggable, and compatible with the React ecosystem.

React Hook Form (which we'll cover later) gets the best of both worlds: controlled-style validation with uncontrolled-style performance.

06 — Form Validation

Why Validate User Input?

Form validation means checking that the data a user enters is correct, complete, and safe before processing it. Without validation, your app would accept garbage data, crash on bad inputs, or open security holes.

🔒 Security

Prevent attacks like SQL injection (malicious database commands) and XSS (malicious scripts). Validation is your first line of defence.

📊 Data Quality

Ensure that email addresses look like emails, phone numbers have the right format, and passwords meet minimum requirements before they reach your database.

✨ User Experience (UX)

Immediate feedback ("this email is invalid") is far better than a confusing error after form submission. Good validation guides users to success.

⚡ Server Load

Catching errors on the client (browser) means bad data never reaches your server, saving bandwidth and processing time.

🚨
Critical rule: Client-side validation (in React) is for UX only. It can be bypassed by anyone with basic browser tools. Always validate again on the server for security.

The Two Types of Validation

🌐 Client-Side Validation

Runs in the browser, in your React code. Fast feedback for users. Never trust this alone for security.


HTML5 attributes React state Library rules

🔧 Server-Side Validation

Runs on your backend (Node.js, Python, etc.). This is the security layer. Always mandatory.


Express.js Joi / Zod Django

When to Validate? — Three Strategies

onChange — Real-time (every keystroke)

Validates as the user types. Great for password strength meters. Can feel intrusive for short fields (shows "invalid email" when they've only typed "j").

onBlur — On field exit (most popular)

Validates when the user leaves a field (clicks away or presses Tab). Feels natural — gives the user time to finish typing before showing an error.

onSubmit — On form submission

Only validates when the user clicks Submit. Simplest to implement, but gives no feedback until the end. Best for very short forms.

07 — Built-in

HTML5 Built-in Validation

Before writing any JavaScript, HTML5 gives you free validation through attributes on your input elements. The browser handles the error messages automatically.

required

Field cannot be empty. The browser won't submit the form until this is filled in.

type="email"

Browser validates that the value looks like an email address (x@x.x format).

minLength / maxLength

Sets minimum and maximum character counts. Great for passwords and usernames.

pattern

A Regular Expression (RegEx) that the input must match. Powerful but complex.

HTML5 validation attributes
<form>
  { /* Email — required + must be valid email format */ }
  <input
    type="email"
    required
    placeholder="your@email.com"
  />

  { /* Password — required, minimum 8 chars, must have a number */ }
  <input
    type="password"
    required
    minLength={8}
    pattern="(?=.*\d).{8,}"   // Must include at least one digit
  />

  { /* Phone — must match pattern XXX-XXX-XXXX */ }
  <input
    type="tel"
    pattern="[0-9]{3}-[0-9]{3}-[0-9]{4}"
    placeholder="555-123-4567"
  />
</form>
⚠️
Limitation: HTML5 validation can be bypassed in React if you call e.preventDefault() without adding your own checks. You also can't easily customize the error message styling. That's why custom validation exists.
08 — Custom Logic

Custom Validation in React

Custom validation gives you full control: you decide what's valid, what the error message says, and when to show it. The pattern involves three things working together: an errors state, a validate function, and conditional rendering of error messages.

The Pattern

User fills formtypes / blurs
→
validate()runs your rules
→
setErrors()updates errors state
→
Show errorsconditional render

Full Example with Custom Validation

CustomValidation.jsx
function SignupWithValidation() {
  const [formData, setFormData] = useState({ email: '', password: '' });
  const [errors, setErrors] = useState({});  // Stores error messages

  // Your validation rules as a function
  const validate = (data) => {
    const newErrors = {};

    if (!data.email) {
      newErrors.email = 'Email is required';
    } else if (!data.email.includes('@')) {
      newErrors.email = 'Please enter a valid email address';
    }

    if (!data.password) {
      newErrors.password = 'Password is required';
    } else if (data.password.length < 8) {
      newErrors.password = 'Password must be at least 8 characters';
    }

    return newErrors;  // { email: 'message', password: 'message' }
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    const validationErrors = validate(formData);

    if (Object.keys(validationErrors).length > 0) {
      setErrors(validationErrors);  // Show errors
      return;  // Stop — don't submit
    }
    // No errors — proceed with submission!
    console.log('Submitting:', formData);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        name="email"
        value={formData.email}
        onChange={handleChange}
      />
      { /* Conditionally show error below the field */ }
      {errors.email && <span style={{color: 'red'}}>{errors.email}</span>}

      <input
        type="password"
        name="password"
        value={formData.password}
        onChange={handleChange}
      />
      {errors.password && <span style={{color: 'red'}}>{errors.password}</span>}

      <button type="submit">Sign Up</button>
    </form>
  );
}
💡
The && trick: In React, {errors.email && <span>...</span>} means "only render the span IF errors.email is truthy." If the string is empty or undefined, nothing renders. This is called conditional rendering.
09 — Industry Standard

React Hook Form

React Hook Form (RHF) is the most popular form library in the React ecosystem. It solves all the pain points of manual form management: boilerplate code, re-render performance, and complex validation logic — all in one small, well-designed package.

Why use it?

Without RHF: You write useState for every field, a handleChange function, a validate function, an errors state, and wire it all up manually. That's a lot of repetitive code.

With RHF: You call useForm(), use register() on each field, and validation rules live right on the field. No boilerplate. No re-renders on every keystroke.

Core API

API What it does Example
useForm() Initializes the form — returns all the tools you need const { register, handleSubmit, formState } = useForm()
register() Connects an input to the form + adds validation rules <input {...register('email', { required: true })} />
handleSubmit() Wraps your submit function — only calls it if validation passes <form onSubmit={handleSubmit(onSubmit)}>
formState.errors Object containing validation errors for each field {errors.email && <p>{errors.email.message}</p>}

Complete RHF Example

LoginForm.jsx — with React Hook Form
import { useForm } from 'react-hook-form';

function LoginForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting }
  } = useForm();

  const onSubmit = (data) => {
    // Only called if all validations pass!
    // 'data' contains all field values automatically
    console.log(data);  // { email: 'x@y.com', password: '...' }
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>

      <div>
        <label>Email</label>
        <input
          type="email"
          {/* register() connects field + adds validation rules inline */}
          {...register('email', {
            required: 'Email is required',
            pattern: {
              value: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
              message: 'Please enter a valid email'
            }
          })}
        />
        {errors.email && <p className="error">{errors.email.message}</p>}
      </div>

      <div>
        <label>Password</label>
        <input
          type="password"
          {...register('password', {
            required: 'Password is required',
            minLength: {
              value: 8,
              message: 'Password must be at least 8 characters'
            }
          })}
        />
        {errors.password && <p className="error">{errors.password.message}</p>}
      </div>

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Logging in...' : 'Log In'}
      </button>

    </form>
  );
}

Why RHF Gets the Best of Both Worlds

⚡ Uncontrolled Performance

Internally, RHF uses refs (not state) for inputs. This means no re-render on every keystroke — much faster for large forms.

✅ Controlled Convenience

You still get real-time validation feedback, easy error access, and all the DX (developer experience) benefits of knowing what's in every field.

📦
Install: npm install react-hook-form — it has zero dependencies and is under 10kb. The most downloaded form library in the React ecosystem.
10 — Professional Standards

Best Practices

Following these practices will make your forms more accessible, user-friendly, and maintainable.

📍
Show errors directly below the relevant input

Don't show all errors in a list at the top or bottom of the form. Users don't know which field the error refers to unless it's right next to the field.

👁️
Use onBlur for validation trigger

Validate when the user leaves a field, not on every keystroke. Showing "invalid email" when someone has only typed two letters is frustrating.

🚫
Disable the submit button while submitting

Prevent double submissions by disabling the button when the form is being processed. Show a loading state so the user knows something is happening.

🏷️
Always use <label> elements

Labels make forms accessible to screen readers and allow users to click the label to focus the input. Use htmlFor in React (same as HTML's for).

🌐
Always validate on the server too

Client-side validation is bypassed easily. Never trust it alone. Your backend must validate all incoming data independently.

♿
Use aria-describedby for error messages

Link error messages to inputs with ARIA attributes so screen readers announce them to visually impaired users.

11 — Watch Out

Common Mistakes

❌
Forgetting e.preventDefault()

HTML forms, by default, reload the page when submitted. This destroys all your React state. You must call e.preventDefault() in your onSubmit handler.

✅ Fix: const handleSubmit = (e) => { e.preventDefault(); /* your logic */ }
❌
Mixing Controlled and Uncontrolled

Using both a value prop and a ref on the same input, or switching between having and not having a value prop. This causes React warnings and unpredictable behavior.

✅ Fix: Choose one approach. If you have value={...}, also have onChange={...}. If you're using refs, use defaultValue, not value.
❌
Initializing state with undefined

If you do useState() (no argument), the initial value is undefined. Setting value={undefined} on an input makes React treat it as uncontrolled. Later when you set it to a string, React warns about switching from uncontrolled to controlled.

✅ Fix: Always initialize string fields with an empty string: useState('')
❌
Showing all errors immediately on load

Running validation on component mount makes every field show an error before the user has typed anything. This is hostile UX.

✅ Fix: Only show errors after the user has interacted with a field (touched it). Track a "touched" state or use onBlur.
❌
Not handling server-side errors

Showing only client-side errors means users won't know about backend issues like "email already taken" or "invalid credentials." These must be displayed in the form too.

✅ Fix: After an API call, check for server errors and set them into your errors state: setErrors({ email: 'This email is already registered' })
12 — Recap

Summary

🎛️

Controlled

State + onChange. React owns the data. Best for most forms. Enables real-time validation.

🔗

Uncontrolled

Refs + DOM. No re-renders. Use for file inputs or when performance is critical.

✅

Validation

HTML5 built-ins + custom React logic. Always validate server-side too. onBlur is the sweet spot.

📦

React Hook Form

Industry standard. Best of both worlds: performance of uncontrolled, UX of controlled.

🛡️

Security

Client-side is for UX only. Server-side validation is mandatory — always.

✨

Good UX

Show errors near fields, validate on blur, disable submit during loading, use labels always.

🚀
Your learning path: Start with controlled components + manual validation to understand how it works. Once comfortable, move to React Hook Form for all real projects — it'll save you hours of boilerplate.
